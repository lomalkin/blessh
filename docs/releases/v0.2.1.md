Bookworm (BlueZ 5.66) works without changing the Bluetooth configuration.

**Upgrading**

- On BlueZ before 5.67, `ble-term.service` turns off the kernel's ECRED
  L2CAP mode before it starts (`/usr/lib/ble-term/eatt-off`). EATT then
  stays off, as in BlueZ 5.67 and later, and phones are no longer asked to
  pair. `Channels = 1` in `/etc/bluetooth/main.conf` is no longer needed;
  it can stay. An explicit `Channels` setting is left alone. Details:
  README, "Bookworm".
- `ble-term.service` is also wanted by `multi-user.target`, so it starts
  on boots where `bluetooth.target` does not come up, e.g. after a systemd
  soft-reboot (the adapter is already there, so udev does not pull the
  target in). The daemon then starts bluetoothd through D-Bus activation,
  which works only while `bluetooth.service` is enabled. The installer
  starts the daemon in that case too, and says so when `bluetooth.service`
  is disabled.
- Correction to the 0.2.0 notes: sntrup761 key exchange takes about 2 s in
  release builds of the ConnectBot BLE client; the 20 s were measured with
  a debug build.

**Changes**

- `tests/e2e-package.sh` checks when the EATT switch applies.
