BLE sessions now follow the system SSH server's configuration.

**Upgrading**

- `/etc/ble-term/sshd_config` now only includes `/etc/ssh/sshd_config`:
  BLE logins get the same settings as network SSH (passwords, allowed
  users, root login, forwarding, limits), including `sshd_config.d`
  drop-ins. Until 0.1.3 BLE had its own settings, with passwords allowed
  even where network SSH refused them. If you edited the file, dpkg asks
  whether to keep your version: take the new one and put settings meant for
  BLE only above its `Include` line. The installer prints the resulting
  policy.
- BLE sessions use the system SSH host keys instead of the package's own
  key. Clients that connected before see a host key change once: compare
  the fingerprint the installer prints (`ssh-keygen -lf
  /etc/ssh/ssh_host_ed25519_key.pub`) and accept it. The old key stays in
  `/etc/ble-term` until the package is purged.
- `MaxAuthTries` and `LoginGraceTime` are no longer lowered for BLE (they
  were 3 and 60 s); the system's values apply (6 and 120 s by default).
- sntrup761 key exchange is no longer excluded for BLE. With OpenSSH 9.x
  (Debian bookworm) ConnectBot may pick it and take about 20 s to connect
  until the client prefers curve25519; OpenSSH 10 (trixie) negotiates
  mlkem768x25519.
- The upgrade ends an active BLE session.

**Changes**

- CI installs the package in clean bookworm and trixie and checks the
  settings BLE sessions get (`tests/e2e-package.sh`).
